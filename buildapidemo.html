Build an NFL Teams & Players API

Introduction to C#, ASP.NET Core Minimal APIs, and Visual Studio Code on macOS

Instructor demonstration • Beginner level • .NET 10

Learning objectives

By the end of this tutorial, students will create a C# project, define Team and Player classes, build REST endpoints, and use a browser or terminal to test JSON responses. This project uses illustrative sample rosters, not live NFL data.

1. Install the software

  1. Install Visual Studio Code.
  2. Install the .NET 10 SDK (Arm64 for Apple Silicon, x64 for Intel). Install the SDK, not only the runtime.
  3. Install the C# Dev Kit extension in VS Code.

Open VS Code → Terminal → New Terminal and verify:

dotnet --version
If you see dquote>, press Control+C. C# source belongs in a .cs file, not directly in the terminal.

2. Create the project

Run these commands one line at a time in the terminal:

mkdir -p ~/Documents/code
cd ~/Documents/code
dotnet new web -n NFLTeamsApi -f net10.0
cd NFLTeamsApi
code .

If code . fails, use VS Code → File → Open Folder → Documents/code/NFLTeamsApi.

Your project now contains NFLTeamsApi.csproj and Program.cs. Always run dotnet run from this project directory.

3. Create the data models

Create a folder named Models. Inside it, create Team.cs:

namespace NFLTeamsApi.Models;

public class Team
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public string City { get; set; } = "";
    public string Conference { get; set; } = "";
}

Now create Models/Player.cs:

namespace NFLTeamsApi.Models;

public class Player
{
    public int Id { get; set; }
    public string Name { get; set; } = "";
    public string Position { get; set; } = "";
    public int JerseyNumber { get; set; }
    public int TeamId { get; set; }
}

Teaching point: TeamId connects a player to a team. It works like a foreign key in a relational database, although this demonstration uses in-memory lists.

4. Write Program.cs — complete application

Replace the entire contents of Program.cs with this code:

using NFLTeamsApi.Models;

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

// Sample data only: not a current NFL roster feed.
var teams = new List<Team>
{
    new() { Id = 1, Name = "Steelers", City = "Pittsburgh", Conference = "AFC" },
    new() { Id = 2, Name = "Chiefs", City = "Kansas City", Conference = "AFC" },
    new() { Id = 3, Name = "Eagles", City = "Philadelphia", Conference = "NFC" }
};

var players = new List<Player>
{
    new() { Id = 1, Name = "T.J. Watt", Position = "LB", JerseyNumber = 90, TeamId = 1 },
    new() { Id = 2, Name = "Patrick Mahomes", Position = "QB", JerseyNumber = 15, TeamId = 2 },
    new() { Id = 3, Name = "Jalen Hurts", Position = "QB", JerseyNumber = 1, TeamId = 3 }
};

app.MapGet("/", () => "NFL Teams & Players API is running!");

// READ: all teams
app.MapGet("/api/teams", () => Results.Ok(teams));

// READ: one team
app.MapGet("/api/teams/{id:int}", (int id) =>
{
    var team = teams.FirstOrDefault(t => t.Id == id);
    return team is null ? Results.NotFound() : Results.Ok(team);
});

// READ: all players
app.MapGet("/api/players", () => Results.Ok(players));

// READ: players belonging to a team
app.MapGet("/api/teams/{id:int}/players", (int id) =>
{
    if (!teams.Any(t => t.Id == id)) return Results.NotFound();
    return Results.Ok(players.Where(p => p.TeamId == id).ToList());
});

// CREATE: add a team
app.MapPost("/api/teams", (Team input) =>
{
    if (string.IsNullOrWhiteSpace(input.Name) ||
        string.IsNullOrWhiteSpace(input.City) ||
        string.IsNullOrWhiteSpace(input.Conference))
        return Results.BadRequest("Name, city and conference are required.");

    input.Id = teams.Count == 0 ? 1 : teams.Max(t => t.Id) + 1;
    teams.Add(input);
    return Results.Created($"/api/teams/{input.Id}", input);
});

// CREATE: add a player to an existing team
app.MapPost("/api/players", (Player input) =>
{
    if (string.IsNullOrWhiteSpace(input.Name) ||
        string.IsNullOrWhiteSpace(input.Position) ||
        input.JerseyNumber < 0 || input.JerseyNumber > 99)
        return Results.BadRequest("Valid name, position and jersey number are required.");

    if (!teams.Any(t => t.Id == input.TeamId))
        return Results.BadRequest("TeamId must refer to an existing team.");

    input.Id = players.Count == 0 ? 1 : players.Max(p => p.Id) + 1;
    players.Add(input);
    return Results.Created($"/api/players/{input.Id}", input);
});

// UPDATE: edit a player
app.MapPut("/api/players/{id:int}", (int id, Player input) =>
{
    var player = players.FirstOrDefault(p => p.Id == id);
    if (player is null) return Results.NotFound();
    if (string.IsNullOrWhiteSpace(input.Name) ||
        string.IsNullOrWhiteSpace(input.Position) ||
        input.JerseyNumber < 0 || input.JerseyNumber > 99 ||
        !teams.Any(t => t.Id == input.TeamId))
        return Results.BadRequest("Invalid player information.");

    player.Name = input.Name;
    player.Position = input.Position;
    player.JerseyNumber = input.JerseyNumber;
    player.TeamId = input.TeamId;
    return Results.Ok(player);
});

// DELETE: remove a player
app.MapDelete("/api/players/{id:int}", (int id) =>
{
    var player = players.FirstOrDefault(p => p.Id == id);
    if (player is null) return Results.NotFound();
    players.Remove(player);
    return Results.NoContent();
});

app.Run();
Explain in class: MapGet reads data, MapPost creates data, MapPut updates data, and MapDelete removes data. Results.Ok sends HTTP 200; Results.Created sends 201; Results.NotFound sends 404.

5. Build and run the API

dotnet build
dotnet run --urls http://localhost:5050

Keep this terminal open while testing. Visit these URLs in your browser:

  • http://localhost:5050/
  • http://localhost:5050/api/teams
  • http://localhost:5050/api/players
  • http://localhost:5050/api/teams/1/players

These links work only while your local server is running.

Expected JSON from /api/teams/1/players

[
  {
    "id": 1,
    "name": "T.J. Watt",
    "position": "LB",
    "jerseyNumber": 90,
    "teamId": 1
  }
]

6. Test POST, PUT, and DELETE from a second terminal

In VS Code choose Terminal → New Terminal. Leave the API running in the first terminal.

Add a team (POST)

curl -i -X POST http://localhost:5050/api/teams \
  -H "Content-Type: application/json" \
  -d '{"name":"Bills","city":"Buffalo","conference":"AFC"}'

Add a player (POST)

curl -i -X POST http://localhost:5050/api/players \
  -H "Content-Type: application/json" \
  -d '{"name":"Sample Rookie","position":"WR","jerseyNumber":18,"teamId":1}'

Update a player (PUT)

curl -i -X PUT http://localhost:5050/api/players/1 \
  -H "Content-Type: application/json" \
  -d '{"name":"T.J. Watt","position":"EDGE","jerseyNumber":90,"teamId":1}'

Delete a player (DELETE)

curl -i -X DELETE http://localhost:5050/api/players/3

Use curl http://localhost:5050/api/players to inspect the updated list.

Important: Data is stored only in memory. Restarting the server restores the original example lists. This project does not access an official NFL API.

8. Hands-on exercise

  1. Add a fourth team to the starter data.
  2. Add two new players assigned to that team.
  3. Create a GET /api/players/{id:int} endpoint that returns a player or HTTP 404.
  4. Create a GET /api/players/position/{position} endpoint using Where and a case-insensitive comparison.
  5. Test each endpoint and capture its JSON response.

Challenge: show players with team names

Create a new endpoint /api/roster that joins the two lists and returns each player's name, position, and team city/name. Discuss how this relates to SQL joins.

9. Discussion question

How is a C# class such as Player similar to a database table? Explain the purpose of TeamId, compare GET and POST requests, and describe one advantage and one limitation of keeping data in an in-memory List<Player> rather than a PostgreSQL database. Respond to a classmate with an additional example.
