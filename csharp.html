1. Learning objectives

By the end of this module, students should be able to:

  1. Explain the roles of C#, .NET, ASP.NET Core, the SDK, and Visual Studio Code.
  2. Create and run C# console applications from the VS Code terminal.
  3. Use variables, data types, conditional logic, loops, methods, collections, and classes.
  4. Describe HTTP, JSON, REST APIs, and client/server communication.
  5. Build and test a small ASP.NET Core Minimal API with GET and POST endpoints.
  6. Use GitHub to submit a reproducible programming project.
Terminology: “.NET Core” was the former product name. Modern versions are called .NET; ASP.NET Core remains the web framework's name. This module targets .NET 10 (LTS).

2. Install and configure your development environment

  1. Install Visual Studio Code.
  2. Install the .NET 10 SDK (not only the runtime).
  3. Open VS Code Extensions and install C# Dev Kit by Microsoft.
  4. Open Terminal → New Terminal and verify the SDK:
dotnet --version
 dotnet --list-sdks

Then create a first application:

dotnet new console -n HelloCSharp
cd HelloCSharp
code .
dotnet run

If code . is unavailable, open the folder using VS Code's File → Open Folder menu. Edit Program.cs and run again. On macOS, you may need to install the code shell command from VS Code's Command Palette.

Troubleshooting: If dotnet is not found, restart VS Code after installing the SDK and check your PATH. If the project does not compile, read the first build error and check braces, semicolons, and spelling.

4. C# fundamentals: lessons and sample code

4.1 Your first C# program

C# is a statically typed, object-oriented language. Modern console templates allow top-level statements, so a separate Main method is not required for these examples.

Console.WriteLine("Hello, C#!");
Console.Write("Enter your name: ");
string name = Console.ReadLine() ?? "Student";
Console.WriteLine($"Welcome, {name}!");

4.2 Variables, calculations, and conditionals

string product = "Notebook";
int quantity = 3;
decimal unitPrice = 7.50m;
decimal total = quantity * unitPrice;

Console.WriteLine($"{product}: ${total:F2}");
if (total >= 20m)
{
    Console.WriteLine("Order qualifies for a discount.");
}
else
{
    Console.WriteLine("No discount applies.");
}

Discuss: Why is decimal commonly preferred over double for monetary amounts?

4.3 Loops, lists, and methods

List<int> scores = new() { 82, 95, 74, 90 };
foreach (int score in scores)
{
    Console.WriteLine($"Score: {score}");
}

double Average(List<int> values)
{
    return values.Average();
}

Console.WriteLine($"Average: {Average(scores):F1}");

4.4 Classes and objects

Replace the contents of Program.cs with the following standalone example:

Book book = new Book("Learning C#", 29.99m);
Console.WriteLine(book.Describe());

public class Book
{
    public string Title { get; set; }
    public decimal Price { get; set; }

    public Book(string title, decimal price)
    {
        Title = title;
        Price = price;
    }

    public string Describe()
    {
        return $"{Title} costs ${Price:F2}";
    }
}

Concept check: A class defines a type; an object is an instance of that class. Properties hold data, and methods describe behavior.

5. Introduction to ASP.NET Core web programming

Web applications commonly separate a client (browser or other application) from a server (ASP.NET Core application). The client sends an HTTP request; the server responds with data, often JSON.

HTTP methodTypical useExample
GETRetrieve dataGET /api/books
POSTCreate dataPOST /api/books
PUTReplace/update dataPUT /api/books/1
DELETERemove dataDELETE /api/books/1

5.1 Create a Minimal API project

Open a new terminal outside the console project and enter:

dotnet new web -n BookApi --framework net10.0
cd BookApi
code .

5.2 Replace Program.cs with this working API

var builder = WebApplication.CreateBuilder(args);
var app = builder.Build();

var books = new List<Book>
{
    new(1, "Learning C#", "Taylor", 29.99m),
    new(2, "Web APIs", "Jordan", 34.50m)
};

app.MapGet("/", () => "Book API is running");

app.MapGet("/api/books", () => Results.Ok(books));

app.MapGet("/api/books/{id:int}", (int id) =>
{
    var book = books.FirstOrDefault(b => b.Id == id);
    return book is null ? Results.NotFound() : Results.Ok(book);
});

app.MapPost("/api/books", (CreateBook request) =>
{
    if (string.IsNullOrWhiteSpace(request.Title) || request.Price < 0)
        return Results.BadRequest("Title is required and price must be nonnegative.");

    int id = books.Count == 0 ? 1 : books.Max(b => b.Id) + 1;
    var book = new Book(id, request.Title, request.Author, request.Price);
    books.Add(book);
    return Results.Created($"/api/books/{id}", book);
});

app.Run();

record Book(int Id, string Title, string Author, decimal Price);
record CreateBook(string Title, string Author, decimal Price);

Why this design? MapGet creates GET routes; MapPost creates a POST route; Results.Ok, Results.NotFound, and Results.Created return meaningful HTTP statuses. Records define simple data models. The list is stored in memory and resets when the server restarts.

5.3 Run and test the API

dotnet run --urls http://localhost:5050

Open http://localhost:5050/api/books in a browser while the server is running. Test the POST route in a terminal:

curl -i -X POST http://localhost:5050/api/books \
  -H "Content-Type: application/json" \
  -d '{"title":"C# Projects","author":"Alex","price":19.95}'

On Windows PowerShell, use curl.exe for curl syntax. If your terminal handles multiline commands differently, enter the command on one line. Use Ctrl+C to stop the server.

5.4 Optional browser front end

Create wwwroot/index.html in the BookApi project. This page uses JavaScript's fetch() to request JSON from your C# API:

<!DOCTYPE html>
<html lang="en">
<head><meta charset="UTF-8"><title>Book Catalog</title></head>
<body>
  <h1>Book Catalog</h1>
  <button id="load">Load Books</button>
  <ul id="books"></ul>
  <script>
    document.querySelector('#load').addEventListener('click', async () => {
      try {
        const response = await fetch('/api/books');
        if (!response.ok) throw new Error('Unable to load books');
        const books = await response.json();
        const list = document.querySelector('#books');
        list.replaceChildren();
        for (const book of books) {
          const item = document.createElement('li');
          item.textContent = `${book.title} — $${book.price.toFixed(2)}`;
          list.appendChild(item);
        }
      } catch (error) {
        alert(error.message);
      }
    });
  </script>
</body>
</html>

To serve the page, add app.UseDefaultFiles(); and app.UseStaticFiles(); after var app = builder.Build(); and before route mappings. Restart the server and open http://localhost:5050/. The existing root GET route returns text at /, so remove or change app.MapGet("/", ...) to let the default index page appear.

Use the same server origin for the HTML and API in this exercise. This avoids cross-origin configuration. The example is instructional and does not include authentication, a database, or production-grade validation.

6. Hands-on lab exercises

Exercise A — Console calculator (20–30 minutes)

  1. Create a new console project named PriceCalculator.
  2. Ask the user for a product name, quantity, and unit price.
  3. Use int.TryParse and decimal.TryParse to validate input.
  4. Calculate the subtotal and apply a 10% discount when the subtotal is at least $100.
  5. Display the final total with two decimal places.

Check: Quantity 4 at $30 each should yield a $120 subtotal and $108 final total.

Exercise B — Classes and collections (20–30 minutes)

  1. Create a Student class with Name and Grade properties.
  2. Create a list of at least five students.
  3. Use a loop to display each student.
  4. Write a method to calculate the class average.
  5. Display students with grades of 90 or higher.

Exercise C — API exploration (30–40 minutes)

  1. Run the Book API and retrieve all books.
  2. Request a book ID that exists and one that does not. Record the status codes.
  3. POST a new book with valid JSON; verify it appears in the GET results.
  4. POST a book with an empty title and explain the error.
  5. Change the API to support GET /api/books/search?author=... (case-insensitive partial author matching).
Hints for Exercise C

Minimal APIs bind query parameters from handler arguments. For searching, try books.Where(b => b.Author.Contains(author, StringComparison.OrdinalIgnoreCase)). Test an author that matches more than one book.

Exercise D — Web page (optional, 20–30 minutes)

Serve the optional HTML page and add a text field that filters displayed books by title on the client side. Use textContent to insert user-visible text safely.

8. Programming assignment — Student Course API

Goal: Build a working ASP.NET Core Minimal API for managing courses. This is an individual assignment that applies C# fundamentals to web programming.

Project name: StudentCourseApi   |   Suggested effort: 4–6 hours   |   Total: 100 points

Required model

Create a Course record or class with: Id (integer), Code (string), Title (string), Credits (integer), and Instructor (string).

Required features

  1. Create the project with dotnet new web -n StudentCourseApi --framework net10.0.
  2. Seed at least five realistic courses in an in-memory list.
  3. Implement GET /api/courses to return all courses.
  4. Implement GET /api/courses/{id} to return a course or HTTP 404.
  5. Implement POST /api/courses to add a course and return HTTP 201.
  6. Implement PUT /api/courses/{id} to update an existing course or return HTTP 404.
  7. Implement DELETE /api/courses/{id} to delete a course or return HTTP 404.
  8. Reject invalid submissions with HTTP 400: blank course code/title/instructor, or credits outside 1–6.
  9. Build a simple HTML/JavaScript page, served by ASP.NET Core, that lists courses using fetch() and displays the course code, title, and credits.
  10. Include a README.md with setup commands, API endpoints, test examples, and screenshots.

Example JSON for POST

{
  "code": "CMPS360",
  "title": "Web Programming",
  "credits": 3,
  "instructor": "Professor Smith"
}

Required testing evidence

Provide screenshots or saved terminal output demonstrating: successful GET all; successful GET by ID; missing ID returning 404; successful POST returning 201; invalid POST returning 400; successful PUT; successful DELETE; and the working browser interface. Explain how you tested the application.

Deliverables

  1. GitHub repository URL with all source files and a .gitignore that excludes bin/ and obj/.
  2. README with prerequisites, run instructions, API routes, and sample JSON.
  3. Eight testing screenshots or equivalent clearly labeled evidence.
  4. A 150–250 word reflection describing what you learned, one issue you debugged, and how the API connects to the browser page.
